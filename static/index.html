      03 · Under the hood

      From pixels to prose in five steps.

      PixelProse chains four transformer networks from Salesforce's BLIP family, all running on your own machine.

      Pre-process

      Resize to 384×384, normalise colours, split into 24×24 = 576 patches of 16 px.

      Vision Transformer

      ViT-L/16 turns each patch into a 1024-d vector using 24 layers of self-attention.

      Text decoder

      A BERT-style decoder writes the caption token by token, attending to image patches via cross-attention.

      Re-ranking

      Beam search + nucleus sampling produce candidates; the ITM model scores which fits the picture best.

      Explain

      Grad-CAM on cross-attention reveals the image region behind every word.

      01

      BLIP captioner

      Bootstrapping Language-Image Pre-training (Li et al., ICML 2022). Pre-trained on 129M image-text pairs and fine-tuned on COCO. Its CapFilt step generates and filters synthetic captions to clean noisy web data.

      • ViT-L/16 encoder · 384 px
      • 12-layer BERT decoder
      • 446M parameters
      02

      Smart decoding

      Beam search keeps the k most probable sentences; nucleus (top-p) sampling adds natural variety. Repetition penalties and n-gram blocking prevent loops like “a dog and a dog”.

      • Beam width 1–10
      • Top-p 0.9, temperature control
      • Guided prefix captioning
      03

      Self-verification

      A separate image-text matching model re-reads each candidate together with the image and outputs a match probability — a second opinion that catches hallucinated objects.

      • ITM head + contrastive (ITC) similarity
      • Score = 0.65·match + 0.35·confidence
      04

      Explainable AI

      We take the gradient of the match score with respect to the cross-attention map (layer 8) and weight the attention by it — Grad-CAM — producing a heatmap for each word.

      • 24×24 patch-level maps
      • Per-token probabilities
      05

      Visual Q&A

      BLIP-VQA encodes your question together with the image, then a decoder generates a short answer. Ask about colours, counts, places or actions.

      • Open-ended answers
      • Chat-style interface
      06

      Engineered for speed

      The image is encoded once and reused for every candidate; models load lazily and are cached; results are memoised by image hash. FP16 on GPUs, FP32 on CPUs.

      • FastAPI + PyTorch
      • LRU caches · thread-safe locks
